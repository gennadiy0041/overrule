# Как устроен Overrule — шпаргалка для защиты

Одна страница простым языком: что делает каждый модуль и что отвечать на технические вопросы.

## В одной фразе

Overrule — ежедневный 5-минутный тренажёр: человек получает документ из своей профессии, «написанный ИИ», с 3–4
спрятанными ошибками и строками-ловушками, отмечает ошибки, получает разбор, а его Judgment Score меняется.
Петля: **Discover** (карта риска) → **Develop** (задание) → **Prove** (рейтинг и отчёт).

## 1. Данные и карта риска (`src/engine/exposure.ts`, `scripts/import-data.ts`)

- Берём открытый датасет исследования OpenAI и UPenn «GPTs are GPTs»: 19 265 рабочих задач по 923 профессиям США.
  Каждую задачу люди пометили: **E1** — ИИ сам ускоряет её минимум вдвое, **E2** — ускоряет с дополнительным ПО,
  **E0** — не ускоряет.
- Формула β: средневзвешенное, где E1 = 1, E2 = 0,5, E0 = 0. Для профессии основные задачи весят 2, остальные 1.
  Для человека вес — как часто он делает задачу (часто 3, иногда 2, редко 1).
- **Проверка честности:** наш код воспроизводит опубликованные оценки всех 923 профессий с расхождением ноль.
  Это юнит-тест `tests/unit/exposure.test.ts`.
- Перцентиль — доля профессий со строго меньшим β. Нашли артефакт в исходном файле: у фармацевтов записано
  0,39999999999999997 вместо 0,4, из-за чего у проджект-менеджеров получалось 64,2% вместо точных 64,1%.
  Мы считаем по точным значениям, тест это фиксирует. Хороший пример «данные важнее эго».
- Что говорить: «Exposure — это про ускорение задачи, а не про исчезновение профессии».

## 2. Поиск профессии (`src/engine/search.ts`)

Человек пишет свою должность как привык («growth marketer»). Ищем по 923 официальным названиям, ~48 500
альтернативным названиям O\*NET и небольшому словарю современных должностей. Если точного совпадения нет —
нечёткий поиск с пометкой «closest match».

## 3. Задание: как создаётся и почему ему можно верить

- **Схема** (`src/engine/drillSchema.ts`): документ разбит на сегменты (предложения и ячейки таблиц), у каждого id.
  Ключ ответов: какие сегменты ошибочны, тип ошибки, серьёзность, объяснение, исправление. Ловушки: строки,
  которые выглядят подозрительно, но верны. Числовые проверки: арифметическое выражение для каждой цифры.
- **Генерация** (`src/server/llm/`): один вызов модели возвращает документ вместе с ключом строгим JSON
  (у Claude — вызов инструмента со схемой в строгом режиме: ответ декодируется прямо по схеме, поэтому поле не
  может прийти не той формы. Принудительный выбор инструмента эта модель не принимает, поэтому об этом её просит
  системная инструкция, а ответ без вызова считается браком и идёт на повтор).
- **Проверка `verifyDrill`** (`src/engine/verifyDrill.ts`) — обычный код, без ИИ: схема; все ссылки на сегменты
  существуют; ловушки не пересекаются с ошибками; минимум три разных типа ошибок; лимиты уровня; **каждая цифра
  пересчитана нашим вычислителем** (`safeMath.ts` — только числа, четыре действия и скобки, никакого `eval`).
  Числовая «ошибка» обязана быть действительно неверной, а все остальные цифры — действительно верными.
- **Запасные пути:** проверка не прошла → один повтор с текстом найденных проблем → Gemini → готовое задание из
  проверенного пула. Пользователь никогда не видит ошибку провайдера.
- **Скорость:** живая генерация занимает 20–40 секунд (замер 15 ноября на проде: около 26 секунд на черновик),
  поэтому первое задание начинает создаваться в фоне сразу после выбора задач в скане, а общее ежедневное
  задание профессии — как только человек закончил скан. В скриптовом прогоне по проду (браузер с короткими
  паузами «на чтение») первое задание появилось через 11–12 секунд после нажатия «старт», ежедневное открылось
  за 2 секунды. Если за 45 секунд не успели — отдаём задание из пула.
- **Деньги:** каждый вызов модели записан в журнал (`llm_calls`). По нему считается расход: токены × цена по
  прайсу, с запасом в большую сторону. Есть потолок в долларах (`LLM_BUDGET_USD`): генерация стартует, только
  если её худший случай ещё помещается. На потолке продукт сам перестаёт звать модели и работает из пула.
  Замер: принятое задание уровня 2 — около $0,05–0,06, оценка заметок — доли цента. Расход виден на `/metrics`.
- **Пул** (`data/pool/`, `scripts/generate-pool.ts`): заранее созданные задания для шести стартовых профессий.
  У них дополнительная **перекрёстная проверка**: другая модель решает задание вслепую, без ключа; оставляем,
  если она нашла хотя бы половину ошибок. Статистика принятых и отклонённых — в `data/pool/stats.json`.
- **Ключ ответов не уходит в браузер до сдачи** — это проверяет API-тест.

Пять типов ошибок: **numbers** (арифметика, проценты), **facts** (выдуманная статистика или источник),
**logic** (вывод противоречит данным), **risk** (правовой и комплаенс-риск), **audience** (не то, что просили).

## 4. Подсчёт (`src/engine/scoring.ts`)

- Попадания считает **код по ключу**, а не нейросеть.
- Баллы: 10 × серьёзность за пойманную ошибку, +5 за верный тип, до +6 за объяснение «почему»;
  −5 за ложный флаг, −8 за флаг на ловушке. Лишние флаги стоят очков: тренируем калибровку, а не подозрительность.
- ИИ участвует только в одном месте: оценивает короткое «почему» (0–2 балла), один вызов на попытку, таймаут 12 секунд.
  Если не ответил — работает простая эвристика по ключевым словам.
- Контрольный пример из теста: 56 очков из 144.

## 5. Judgment Score (`src/engine/elo.ts`, `adaptive.ts`)

- Это рейтинг Эло, как в шахматах, только «соперник» — уровень задания: сложности 800 / 950 / 1100 / 1250 / 1400,
  старт с 1000. Сыграл лучше ожидаемого — рейтинг растёт.
- Следующий уровень подбирается чуть ниже рейтинга (сложно, но выполнимо).
- Слабое место — тип ошибок с худшим процентом поимки за последние 10 заданий; он обязательно попадает в
  следующее персональное задание.
- Перцентиль показываем только среди реальных игроков и только когда их наберётся 20. До этого честно пишем
  «Percentile unlocks at 20 players».

## 6. Daily Catch (`src/engine/daily.ts`, `src/server/services/drillService.ts`)

- Одно общее задание на профессию в сутки по времени Нью-Йорка. Номер считается от 14 ноября 2026 (#1).
- Для стартовых профессий задание берётся из пула по кругу; для остальных создаётся при первом запросе за день
  и кэшируется.
- Шеринг как в Wordle: зелёный — поймал с верным типом, жёлтый — поймал с другим типом, красный — пропустил,
  чёрный — ложный флаг.
- Серия — сколько дней подряд была хотя бы одна попытка.

## 7. Сессии, тарифы, оплата

- Без регистрации: анонимная cookie. Персональных данных не собираем.
- Free: карта, Daily Catch, серия, рейтинг. Pro: персональные задания, тренировка слабого места, Weekly Debrief,
  Review Report, полная история.
- Чекаут демонстрационный, без полей карты, с плашкой об этом. Он включает 7-дневный триал и пишет событие в воронку.

## 8. Демо-профиль (`src/server/services/demo.ts`)

История «Jess» не нарисована руками. Скриптовый игрок проходит неделю заданий из пула через **настоящий движок**:
тот же подсчёт и тот же Эло. Поимка растёт с ~50% до ~80%, ложных флагов становится меньше, слабое место — risk.
Каждый посетитель получает свою копию и может сыграть сегодняшний Daily Catch.

## 9. Отчёт, дебриф, календарь

- **Weekly Debrief** и **Review Report** собираются по шаблону из записей о попытках — без нейросети, ничего не выдумано.
- Отчёт — публичная страница `/r/…` для печати, с кнопкой «скопировать текст для self-review» и оговоркой
  «Not an employer certification».
- Напоминание — файл `.ics` с ежедневным повтором.

## 10. Метрики (`/metrics?token=…`)

События воронки пишутся в SQLite. Страница показывает воронку по уникальным сессиям, возвраты на следующий день,
прохождения Daily Catch, ответы опросов (с N) и статистику вызовов моделей. Наш собственный трафик
(тесты, `/?internal=1`, демо-профиль) исключён.

## 11. SEO-страницы

923 страницы «Will AI replace {профессия}?» рендерятся на сервере из тех же данных, есть `sitemap.xml`.
Это бесплатный канал привлечения: человек ищет свою профессию, видит разбор по задачам и переходит в скан.

## 12. Стек

Bun + Hono (API и серверные страницы), React + Vite + Tailwind (интерфейс), SQLite на томе Railway, zod для
проверки всех входных данных. Чистая логика лежит в `src/engine` и покрыта юнит-тестами; отдельный тест проходит
весь путь через API. CI на GitHub Actions: проверка типов, тесты, сборка.

## Короткие ответы на технические вопросы

| Вопрос | Ответ |
| --- | --- |
| Это обёртка над ChatGPT? | Нет. Модель — сменный генератор. Своё: карта задач на открытых данных, ключ к каждому заданию, проверка кодом, подсчёт кодом, Эло, история суждений. |
| Что если Claude недоступен? | Повтор → Gemini → проверенный пул. Пользователь ошибку не увидит. |
| Откуда уверенность, что в задании ошибки настоящие? | Числовые ошибки доказаны пересчётом. Для пула другая модель решает задание вслепую. Логические и аудиторные ошибки проверить кодом нельзя — это честное ограничение. |
| Почему не `eval` для арифметики? | Выражения пишет модель. Свой разборщик принимает только числа, действия и скобки. |
| Можно ли подсмотреть ответы? | Ключ не отдаётся клиенту до сдачи; это проверяет тест. |
| Почему SQLite? | Один процесс, один том, 24 часа. Миграции есть, перейти на Postgres несложно. |
| Как считаете рейтинг честно? | Слепые задания, ключ ответов, формула Эло, штраф за лишние флаги. |
| Что с персональными данными? | Их нет: анонимная cookie, без почты и имён. |
